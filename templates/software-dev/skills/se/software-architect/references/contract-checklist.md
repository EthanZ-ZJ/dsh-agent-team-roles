# 契约清单（草案模板 / 兼容窗口 / 契约测试 / 示例）

> 用途：写接口契约、数据或事件 Schema、版本与兼容策略、迁移窗口，以及把契约验收例交给 TSE。
> 承接合并前 SE 契约 skill（44 行版本）的全部契约细则；SKILL.md §5 只保留硬规则，细节在这里。
> 方法来源：Nygard ADR、语义化版本与扩展-迁移-收缩（expand/migrate/contract）实践。全部离线，直接复制填空。

## 一、契约草案五段（复制后逐段填，不许留空段）

```markdown
## 1. 范围与证据
- 问题：<要解决什么>
- 非目标：<这次不做什么>
- 当前行为及出处：<文件/路径/版本>
- 假设 / 待确认项 / 负责人：<每条一行>

## 2. 边界与权威
- 生产者：<谁写>
- 消费者：<谁读，列全>
- 数据所有者：<谁拥有这份数据>
- 唯一权威位置：<契约文件或类型定义路径；其他位置只引用>
- 读写权限：<谁能写、谁只能读>

## 3. 行为
- 输入 / 输出：<字段、类型、约束>
- 必填 / 可选；缺失 / 空值 / 默认值：<逐个说明，缺失 ≠ null>
- 不变量与校验位置：<在哪一层校验什么>
- 错误语义：<错误码/错误类型；调用方能否重试、重试后的语义>
- 异步（如适用）：幂等键、重复投递、乱序、超时、积压处理
- 权限与数据边界：<谁负责检查，越权返回什么>

## 4. 兼容与发布
- 旧消费者 → 新生产者：<怎样运行>
- 新消费者 → 旧生产者：<怎样运行>
- 混合版本共存：<灰度/滚动发布期间的行为>
- 何时允许停止兼容：<观测信号 + 阈值>
- 迁移路径：<扩展 → 迁移验证 → 收缩，是否可行>
- 回滚边界与不可逆点：<回滚到哪一步；不可逆之后怎么恢复>

## 5. 验收
- 正常例：<前置条件 / 操作 / 可观察结果 / 预期副作用>
- 失败或边界例：<同上>
- 混合版本例（跨版本时）：<同上>
- 不能验证的条件及所需证据：<单列，附负责人>
```

## 二、兼容窗口与迁移清单

- [ ] 三种运行方式都写了吗：旧客户端→新服务、新客户端→旧服务、混合版本？
- [ ] 版本策略写了吗：新增字段/接口怎么加、怎么弃用、破坏性变更怎么走？
- [ ] 破坏性变更是否已开 ADR（见 `adr-template.md`）？
- [ ] 迁移是否按「扩展 → 迁移验证 → 收缩」写，而不是一次性替换？
- [ ] 停止兼容的观测信号与阈值写了吗（例：旧版本调用占比 < 0.1% 连续 7 天）？
- [ ] 回滚边界在哪、回滚后旧数据能否被正确处理？
- [ ] 不可逆点写了吗？不可逆之后恢复路径是什么？
- [ ] **已发出的事件/已写入的数据不能靠回滚消费者或回滚代码消除**——写清对账、重放或补偿方案。

## 三、契约测试与 TSE 交接

契约验收例不是「跑一下看看」，而是 TSE 能直接转成用例的输入：

1. 每个契约给 1 个正常例 + 1 个失败例；跨版本再加 1 个混合版本例。
2. 每个例子写：前置条件、操作、可观察结果、预期副作用（写入了什么、发了什么事件）。
3. 幂等与重复投递要能测：同一事件/请求 ID 重投两次，结果与一次相同。
4. 不能自动验证的条件（如第三方行为、生产数据分布）单列「所需证据 + 负责人」。
5. 契约变更后提醒 TSE：已写用例可能失效，需同步更新。

## 四、示例：队列事件增加可选字段（原 skill 保留）

假设生产者要在 `TaskQueued` 中新增 `priority`。约定权威 Schema 定义缺失等同 `normal`，显式 `null` 与未知值非法；消费者不应在未确认旧版本能忽略未知字段前启用发送。消费者先支持旧消息和新字段，生产者再开启发送。验收包括：旧消息仍按 `normal` 入队；`null` 进入既有无效消息处理流程且不创建任务；相同事件 ID 重投不会重复创建任务。若无效消息率超过约定阈值，先关闭生产者发送新字段，再核实积压中的新消息是否仍可消费；不能仅靠回滚旧消费者来消除已发出的消息。

该示例同时演示了四条规则：缺失值有明确语义（`normal`）、未知值非法、消费者先行（扩展-迁移-收缩）、已发消息不可回滚（靠对账/消费而非回滚消除）。

## 五、契约自检（交付前 10 条）

- [ ] 1. 唯一权威路径写清，其他位置只引用？
- [ ] 2. 生产者、消费者、数据所有者、谁能写/谁只能读都写了？
- [ ] 3. 输入/输出、必填/可选、缺失 vs 空 vs 默认值写清？
- [ ] 4. 不变量与校验位置写清（在哪层校验什么）？
- [ ] 5. 错误语义与可重试性写清？
- [ ] 6. 异步接口的幂等、重复、乱序、超时、积压写清？
- [ ] 7. 三种运行方式（旧→新、新→旧、混合）都覆盖？
- [ ] 8. 迁移有停止信号、回滚边界、不可逆后恢复路径？
- [ ] 9. 正常例 + 失败例 +（跨版本）混合例齐全，TSE 可直接转用例？
- [ ] 10. 没有两处以上手抄同一字段/错误码/枚举/权限点？

## 六、反例（出现即改写）

- 只写 happy path，不写失败与重试语义。
- 破坏性变更不标版本、不开 ADR。
- 把内部数据结构直接暴露为公共契约。
- 同一字段/错误码在契约、代码、文档各定义一份，没有生成标记。
- 迁移写「直接替换」，没有共存期与停止信号。
- 契约改完不通知消费者，也不更新 TSE 用例。
