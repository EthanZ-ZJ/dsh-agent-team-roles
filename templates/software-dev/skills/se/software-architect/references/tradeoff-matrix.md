# Trade-off 矩阵与约束记录

> 用途：≥2 个真实可行选项、质量属性互相拉扯时的选型对比；只有 1 个选项时写约束记录。
> 方法来源：ATAM 的敏感点/权衡点、Hard Parts 的耦合与数据维度、Type 1/2 可逆性。离线可复制。

## 一、先判断该不该做矩阵

做矩阵，当且仅当：

- 存在 ≥2 个真实可行选项；**且**
- 至少两个质量属性互相拉扯（性能 vs 成本、一致性 vs 可用性、交付速度 vs 可维护性、安全 vs 易用性）；**或**
- 需要向 Lead/PM 解释「为什么贵」「为什么慢」「为什么不能更快」。

不做矩阵：只有一个选项（写约束记录）；选项差异只在一行代码；决策完全可逆且成本低于做矩阵的时间（L0/L1）。

## 二、固定维度（不许换成「好不好」）

| 维度 | 怎么填 | 依据来源 |
|---|---|---|
| 关联 ASR | 列出被这条决策影响的 ASR 编号 | §2 场景表 |
| 一次性成本 | S/M/L 或人日区间 + 不确定性 | 估算，标区间 |
| 持续成本 | 运维人力、云账单、许可、监控 | 运维/财务口径 |
| 团队熟悉度 | 高/中/低 + 证据（做过几个项目） | 事实或标「假设」 |
| 可逆性 | 双向门（可快速回退）/ 单向门（难回退） | Type 1/2 判据 |
| 运维负担 | 部署、监控、回滚、排障、值班 | 与现状对比 |
| 合规/安全 | 是否引入新审计面、数据出境、权限模型 | 合规要求 |
| 迁移成本 | 从现状切过去要几步、共存期多久 | 迁移方案 |

维度一旦选定，所有选项用同一组维度；禁止给某个选项单独加有利维度。

## 三、矩阵模板（复制填空）

```markdown
| 维度 | 选项 A：<名称> | 选项 B：<名称> | 选项 C：维持现状 |
|---|---|---|---|
| 关联 ASR | ASR-1, ASR-3 | ASR-1 | ASR-1 |
| 一次性成本 | M（约 2–3 人周，±1 周） | S（约 1 人周） | 0 |
| 持续成本 | 1 个新集群 + 值班 | 无新增 | 现有债继续计息 |
| 团队熟悉度 | 低（无生产经验，假设） | 高（现有栈） | 高 |
| 可逆性 | 单向门（数据格式变了） | 双向门 | — |
| 运维负担 | 高（多一套监控/回滚） | 低 | 低 |
| 合规/安全 | 需新增审计日志 | 沿用现有 | 沿用现有 |
| 迁移成本 | 3 步，共存 2 周 | 0 | 0 |
| **结论** | 只在 ASR-1 的 P95 指标必须 ≤50ms 时选 | 默认推荐 | 若 ASR-1 可放宽则不动作 |
```

## 四、打分规则（防假精度）

1. **先定性，再定量**。高/中/低必须附一句判据；能给出区间就给区间，不给单点数字。
2. **权重写依据**。权重来自哪条 ASR、哪个硬约束，写在同一行；无依据的权重删除。
3. **禁止加权总分掩盖分歧**。总分只能做排序辅助；结论必须写出「哪个维度在拉扯」。
4. **敏感点单独标**：这个决策对哪个质量属性最敏感（例：可用性对跨区复制延迟高度敏感）。
5. **权衡点单独标**：哪两个属性此消彼长（例：一致性 vs 可用性；成本 vs 延迟）。
6. 无法核实的数字标「假设，待验证」，并写验证方式（PoC / 压测 / 供应商报价）。

## 五、结论段模板（必须有）

```markdown
推荐：<选项 B>
理由：1) <对应 ASR-1>；2) <成本/可逆性>；3) <团队可执行性>。
代价：<明确写出放弃了什么>。
置信度：中（因为 <哪个假设未被验证>）。
重审触发：<信号> 出现时重审，例如 P95 > X、日活 > Y、成本 > Z、团队规模 > N。
不选 A 的原因：<一句话>。不选 C 的原因：<一句话>。
决策人：<Lead/用户>，截止 <时间>。
```

低置信度不是不交付的理由：落盘 + 标重审条件，比拖到「想清楚」更安全。

## 六、约束记录（只有一个可行选项时）

不写伪 ADR，写 5 行约束记录，放进 `docs/` 或设计文档附录：

```markdown
## 约束记录：<主题>
- 背景：<为什么现在必须选>。
- 唯一选项：<选项>，因为 <硬约束 1/2>（引用需求/合规/现有栈）。
- 代价：<接受了什么>。
- 第二选项出现的条件：<什么变化会让它变成真选项，例：引入多租户、QPS 翻 10 倍>。
- 决策人 / 日期：<Lead/用户> / YYYY-MM-DD。
```

## 七、反例（出现即改写）

- 选项 B 是明显劣化的陪衬——删掉，改成「为什么只有一个真选项」。
- 只列优点、不写放弃原因——每个未选选项必须有一句放弃原因。
- 权重拍脑袋（性能 40%、成本 30%…）没有依据——改定性 + 判据。
- 结论写「建议进一步评估」——这不是结论；给推荐 + 置信度 + 重审条件。
- 忽略「延后决策」「先做 1 周 PoC」——它们常是真实选项，必须出现在矩阵里。
