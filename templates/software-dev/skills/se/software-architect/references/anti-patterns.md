# 反模式清单与替代动作

> 用途：输出前自检；发现自己写不出具体判据时，回到这里找替代动作。
> 目标读者是模型：每条都是「信号 → 为什么有害 → 改成什么」，不是道德劝告。

## 一、空话与伪架构

| 信号 | 为什么有害 | 替代动作 |
|---|---|---|
| 「高内聚、低耦合」 | 没指名模块与依赖，无法验证 | 指名：哪两个模块、哪条依赖、什么变更会痛、怎么度量 |
| 「遵循最佳实践」 | 最佳实践有适用条件，换上下文就是坑 | 给出适用条件 + 一个反例 + 本项目为何满足条件 |
| 「采用微服务/事件驱动」 | 把手段当结论，忽略组织与数据成本 | 先写「单体哪里不够」，再列分布式代价（见 SKILL.md §4） |
| 只列技术栈，不写放弃代价 | 评审无法判断，等于选型广告 | 每个技术选择至少一条「放弃它是因为…」 |
| 画图代替决策 | 图漂亮但没回答「选哪个」 | 每张图标注它回答的问题；没有问题的图删掉 |
| 质量属性只有形容词 | 不可测、不可验收 | 转六要素场景，带 response measure |
| 大段代码/schema 贴进文档 | 会过期、难读、与代码重复 | 链接到权威文件，只留决策相关片段 |

## 二、过度设计（为架构而架构）

| 信号 | 替代动作 |
|---|---|
| 为「未来可能的 10x」设计分片/多活 | YAGNI：写下触发信号（日活 > X、P95 > Y、成本 > Z），写出前不做 |
| 默认微服务/事件驱动/K8s | 默认单体模块化优先；升级必须给触发条件与迁移成本 |
| 抽象层/插件化只有一个消费者 | 第二个消费者出现前不加抽象；无第二使用者的抽象删除 |
| 引入新技术但无 PoC、无运维方案 | 必须给 PoC 结论或明确风险；没有监控/回滚方案不引入 |
| 文档 30 页、图 20 张 | L0–L3 分级 + 页数上限；删掉「删了不影响决策」的内容 |
| 把可逆决策当单向门慢慢评审 | 用可逆性分级：双向门快速决策，单向门才重流程 |
| 为一个需求引入新框架/新中间件 | 先查现有栈能否解决；新组件的持续成本写进矩阵 |
| 先选技术再找问题 | 从 ASR 出发；没有 ASR 支撑的技术选择删除 |

**YAGNI 触发条件写法**（必须可观测）：

```text
现在不做 <能力>。触发条件：<指标> 连续 <时长> 超过 <阈值>，或 <事件> 发生。
届时需要 <动作>，成本约 <S/M/L>。
```

## 三、越权

| 越权行为 | 正确做法 |
|---|---|
| 自行决定功能优先级、砍需求、改验收标准 | 列选项 + 成本 + 影响，交 PM/Lead；SE 只做技术可行性判断 |
| 承诺排期/人力 | 只给相对成本（S/M/L）与不确定性来源，排期归 Lead |
| 自己宣布「评审通过/测试通过」 | 评审结论归 CR，动态验证归 TSE；SE 只提供可验证点 |
| 直接改实现代码「证明方案可行」 | 只写 `docs/` 与契约/类型定义；PoC 需求转给 DEV/TSE |
| 替用户判断「风险可接受」 | 列风险 + 影响 + 缓解，标「需 Lead/用户确认」 |
| 私自改契约让实现好写 | 契约变更走 ADR/评审，通知下游 |

## 四、文档与事实

| 信号 | 替代动作 |
|---|---|
| 编造性能数字、团队约定、接口行为 | 每条事实标来源：仓库路径 / 需求条目 / ADR / 「假设，待确认」 |
| 把推断写成事实 | 显式三分：事实 / 推断 / 假设 |
| 文档与 ADR 冲突或重复 | 单一权威：决策放 ADR，方案放设计文档，字段放契约，互相引用 |
| 没有 non-goals | ≥3 条 non-goals + 原因，否则范围必然膨胀 |
| 没有未决问题 | 通常等于没审；列问题 + 决策人 + 截止 |
| 文档没有读者与用途 | 每节开头写「谁读、要回答什么」；没有读者的节删掉 |

## 五、边界冲突时的处置（与其他角色）

| 场景 | 处置 |
|---|---|
| PM 需求不可测 | 退回 PM 补验收标准，或 SE 写「假设场景」交 Lead 确认；不替 PM 补产品决策 |
| Lead 要求直接给结论，跳过备选 | 给结论 + 一句话代价 + 置信度；L3 仍必须留 ADR，可写「Lead 决定，SE 保留异议记录」 |
| DEV 发现契约不可实现 | 通过 Lead 回到 SE 仲裁；SE 更新契约并通知下游，不私下让 DEV 绕开 |
| CR 提出架构级问题 | CR 只出缺陷报告；架构修改由 SE 决定并更新 ADR/契约 |
| 用户要求「按最佳实践做」 | 转成具体 ASR 与约束；没有可测目标不进入设计 |
| 时间压力要求降档 | 允许降档，但必须写约束记录 + 补齐信号；不允许删掉风险登记与回滚点 |

## 六、一票否决（出现即停止交付，先修正）

- 没有来源的关键事实（数字、团队约定、接口行为）。
- L3 决策只有 1 个选项且没写约束记录。
- 质量属性没有可测场景。
- 契约有 ≥2 处手抄定义且无权威路径。
- 数据变更没有回滚点。
- 替 Lead/PM 做了范围或优先级决定。
- 越权宣布评审/测试通过。

## 七、三问收尾（每次输出前）

1. 删掉这段，决策会变吗？不会 → 删。
2. 第二个消费者今天存在吗？不存在 → 不加抽象。
3. 每个数字/约定有来源吗？没有 → 标假设或删。
